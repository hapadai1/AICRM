# 계약 흐름 상태·버튼 설계 (현업 확정 2026-07-31, 구현 완료)

계약서·컨설팅·주문·채촌의 상태와 버튼 관리 설계.
원칙: **계약서만 버전관리**하고, 컨설팅·주문·채촌은 최종 상태만 관리한다.
계약서-컨설팅-주문은 1:1:1. 최소 단계는 `CRM 설계_0726_son.pdf` 기준.

## 0. 전체 구조

```
[계약 축 = 마스터 스위치]  작성중 ── 서명완료 ── 계약완료          (버전관리는 여기만)
                            ▲ 수정하기로 복귀                │
컨설팅  : 계약 축에 종속 — 계약 작성중 + 품목 미진행일 때만 수정  │
주문    : ──────────────── 계약완료 시 생성 ──► 이후 자체 상태로 독립 진행
채촌    : 완전 독립 축 — 계약 상태와 무관, 언제든 수정
```

핵심 규칙 두 줄:
> **계약 변경(수정하기)은 품목 추가 전용이다 — 주문으로 물리화된 품목은 줄일 수 없다.**
> **취소·삭제는 주문이 생기기 전에만 가능하다. 취소는 종결이다(수정하기 없음).**

## 1. 계약서 — 마스터 축 (버전관리 O)

상태값: `DRAFT`(작성중) / `SIGNED`(서명완료) / `COMPLETED`(계약완료) / `CANCELLED`(취소)
라벨은 **'작성중'으로 통일** (현업 확정 2026-07-31 — '진행중' 아님).

| 상태 | 계약서 | 컨설팅 | 주문 | 취소·삭제 | 화면 버튼 |
|---|---|---|---|---|---|
| 작성중 (주문 없음) | 수정 ○ | 수정 ○ | 없음 | ○ | 임시저장 · 서명하기 · 계약 취소 |
| 서명완료 (주문 없음) | 잠금 | 잠금 | 없음 | 취소 ○ | 계약서 출력 · 계약완료 · **수정하기** · 계약 취소 |
| 계약완료 | 잠금 | 잠금 | 생성·진행 | ✕ | 계약서 출력 · **수정하기** |
| 작성중 (수정하기 후, 주문 있음) | 품목 추가만 | 미진행 품목만 | 진행 계속 | ✕ | 임시저장 · 서명하기 (취소 버튼 없음) |
| 취소 | — | — | — | 삭제 ○ | (종결 — 수정하기 없음) |

- **[수정하기]는 버튼 하나, 라벨·위치 동일.** 사용자는 두 기능을 구분하지 않는다.
  - 서명완료에서: 서명만 해제하고 작성중 복귀. **버전 그대로**. 이후 다시 서명받는다.
    (서명본 스냅샷은 남기지 않는다 — 감사로그로 추적. 현행 유지.)
  - 계약완료에서: **버전업**(사유 필수) 후 작성중 복귀. 수정 후 다시 서명 → 다시 계약완료.
- 서명하기 조건: 작성중 + 컨설팅 전 품목 확정. 계약완료 → 자동 상태완료 + 주문 물리화(수동완료 없음).
- **취소 = 작성중·서명완료 + 주문 없음.** 주문이 생긴 계약은 취소 불가 — 실물 정리는 렌탈 메뉴·오프라인.
  취소는 종결 상태(수정하기·복구 없음). 필요하면 새 계약을 작성한다.
- **삭제 = 임시저장·취소 + 주문 없음.** (작성중이 "완료 후 재작성"을 겸하므로 주문 존재로 가른다.)
- **수량 감소는 주문으로 물리화되지 않은 품목만** 뒤 순번부터 지운다. 물리화된 품목이 걸리면
  저장 자체를 거부한다: "…은(는) 주문이 진행 중이라 수량을 줄일 수 없습니다. 수정하기에서는 품목 추가만 가능합니다."
- 품목 추가(수량 증가·새 라인)는 작성중에서 항상 자유. 새 품목만 컨설팅을 다시 한다.

## 2. 컨설팅 (스타일 컨설팅 = 맞춤 옵션 + 렌탈 선택) — 계약 축에 종속 (버전관리 X)

- 세부 상태 4개는 진행률 표시용으로 유지: 미시작 → 진행중 → 확인대기 → 확정.
- **편집 가능 = 계약 작성중(DRAFT) + 품목 미진행(제작요청 전).** 그 외는 전부 보기 전용.
  - 서버: 옵션 세션 7개 변이 API + 렌탈 선택 5개 변이 API에 가드.
  - 화면: 계약 옵션 화면 상단 안내 배너 + [옵션 선택]→[옵션 보기] 전환 + 인라인 입력 잠금
    + [옵션 변경]·[최종 저장(확정)]·[계약금액 반영] 버튼 숨김.
- 제작 진행 중 품목 차단 메시지가 경로를 안내한다:
  "제작 진행 중인 품목은 옵션을 변경할 수 없습니다. 제작·입출고 화면에서 상태를 되돌린 뒤 진행해 주세요."
- 내부 세션 번호(selectionVersionNo)는 화면 비노출 시스템 관리용 — 유지.

## 3. 주문 (제작·입고/출고) — 계약과의 접점 2곳, 이후 독립 (버전관리 X)

**주문에는 자체 취소가 없다.** 품목·구성품 상태 전이에서 취소 직접 진입을 서버가 거부한다.
부분 사고(1벌만 제작 불가 등)는 [되돌리기](사유 필수)로 상태를 되돌리고, 실물은 오프라인·렌탈 품목으로 처리한다.

**계약 축과 만나는 지점:**
1. **생성**: 계약완료 시 자동 생성 (유일한 경로)
2. **재완료 동기화**: 재계약완료 시 추가 품목만 주문에 증분 반영. 기존 품목은 건드리지 않는다.

**계약서를 수정하기로 되돌려도 제작·입출고는 멈추지 않는다.**

세부 상태는 제작 관리 화면에서 품목별 수동 완료 버튼으로 진행 — PDF 최소 단계와 1:1:

| PDF 단계 | 품목 상태 | 완료 버튼 |
|---|---|---|
| 발주 요청 | 제작 요청 | [제작요청 완료] |
| 가봉 입고 | 가봉 입고 | [가봉입고] |
| 가봉 피팅 | 가봉 완료 | [가봉 기록] |
| 완성복 입고 | 입고 | [입고] (날짜) |
| 완성복 출고/완료 | 출고 | [출고] (날짜) |

- 구성품 단위 진행 + 품목 집계(부분 입고/출고). 렌탈은 예약→입고→출고. 역행은 사유 필수.
- 주문 헤더 상태는 생성/취소 2개만 표시(진행중·완료 라벨 삭제). 진행 상태는 품목이 담당.

## 4. 채촌 — 완전 독립 축 (버전관리 X)

**언제든 수정, 저장하면 그대로 반영. 새 기록은 [신규 채촌]으로 등록** (회차 V1, V2…는 등록 시에만 증가).

- 상태는 작성중/완료 2개. **완료는 "작업지시서에 쓸 수 있다"는 표시일 뿐 수정을 막지 않는다**
  → 완료 후에도 [저장] 활성 (백엔드는 감사로그 '완료 후 수정' 기록). [완료 해제]는 표시 되돌리기용.
- 예외 하나: **작업지시서에 이미 출력된 채촌만 잠금(locked)** — 출력물 근거 보존. 고치려면 새로 등록.

## 4-b. 베스트(3피스) — 컨설팅에서 벌마다 정한다 (현업 확정 2026-08-01)

**계약서는 베스트를 다루지 않는다.** 계약 시점에는 3피스로 갈지 알 수 없고(옷을 고르면서 정한다),
베스트 값도 그때그때 달라 금액을 자동으로 계산할 수 없다. 품목표에 상의·하의 행이 없는데
베스트만 자기 행을 갖던 것도 이 화면의 어색함이었다.

- **부위 구성**: 정장은 맞춤·렌탈 모두 상의·하의·베스트 세 부위로 만들어진다
  (`COMPONENT_MAP.SUIT`, 마이그레이션 20260801010000 — 기존 렌탈 정장에도 소급 생성).
  렌탈은 베스트 재고를 따로 갖고 있는데 부위가 없어 3피스를 빌려줄 수 없었다.
- **켜고 끄기는 컨설팅 단독**: 컨설팅 목록 베스트 행의 [베스트 제외] 체크박스
  (`POST /contracts/items/:id/vest {included}`) — 체크(제외)·해제(재포함)를 한 엔드포인트로 왕복한다.
  계약서에 경로가 없으므로 반드시 양방향이어야 한다.
  허용 = **계약 작성중 + 품목 미진행** (컨설팅 잠금과 동일 가드).
- **syncContractItems 는 VEST를 건드리지 않는다**: 벌을 새로 만들 때만 세 부위를 붙인다.
  예전처럼 라인 값에 맞추면, 컨설팅에서 뺀 뒤 계약서에서 금액을 수기로 고쳐 저장하는 순간
  (바로 그 흐름이다) 제외가 풀려 되살아난다.
- **금액은 수기**: 베스트를 빼도 계약 금액은 그대로다. 확인서 [최종 저장(확정)] 팝업의
  "계약서 변경내용"에 옵션 추가금과 함께 **"베스트 제외 · 계약서에서 수기 조정"**을 알린다.
  다만 이미 반영한 베스트 *옵션 추가금*은 되돌린다(고른 적 없는 옵션의 돈이 남으면 안 된다).
- **계약서에 남는 자리**: 계약서 선택 옵션 칸에 `베스트 — 제외`, 엑셀 옵션 목록에
  "베스트 제외 — 정장 #n". 3피스로 계약하고 2피스로 만든다는 사실이 보이는 유일한 곳이다.
- **단계 구성은 품목의 부위를 따른다**: 2피스는 `VEST_*` 단계가 진행률·확정 검증·복사에서 빠진다.
  단 **컨설팅 목록만은 제외한 베스트도 행으로 남긴다** — 체크를 다시 풀 자리가 있어야 한다.
  재포함 후 VEST 단계 미선택이면 consultingReadiness 가 서명을 다시 막는다.
- **주문 반영은 재계약완료 시점**: syncOrders 증분 — VEST 생성/되살림, 제외는 CREATED 구성품만 취소.
  작업지시서 조끼 벌수는 취소 구성품을 세지 않는다.
- **`ContractLine.vestIncluded`·`vestUnitPrice` 컬럼은 남겨 둔다**: 이미 베스트 단가가 금액에
  들어간 기존 계약의 근거다. 신규 저장·화면·문서에서는 쓰지 않는다.

## 6. 하지 않는 것

- 새 상태값·새 테이블·마이그레이션 없음 (스키마 변경 0)
- 컨설팅 세션 버전 노출·개편 없음, 주문 버전관리 없음
- 취소 회생 없음(종결), 주문 품목 단위 취소 없음
- 채촌 상태 체계 개편 없음

## 7. 알고 있는 트레이드오프 (표준 대비, 의도적 선택)

- '계약완료'는 생애주기 끝이 아니라 "계약 성립" 의미 — 종결 추적은 여정(진행 단계)이 담당.
- 완료 계약 수정 중에는 목록·통계에 '작성중'으로 보인다 — 통계에서 "작성중=신규"로 세지 말 것.
- 서명 해제 시 서명본 파일은 보관하지 않는다(감사로그만). 분쟁 대비가 필요해지면 소프트 보관으로 전환.
