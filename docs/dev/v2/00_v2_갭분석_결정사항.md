## 2. 확정 결정사항 (D1~D8)

> 하위 설계서는 아래 결정을 전제로 작성한다. 결정 변경 시 본 문서를 먼저 개정한다.

### D1. 고객/관리자 모드 — 매장 태블릿, 직원 조작
- **동일 관리자 로그인** 유지. 좌측 메뉴 최하단 **모드 전환 버튼**으로 UI 모드만 전환한다.
- 관리자 모드 복귀 시 **비밀번호 재입력**(재인증). 고객 모드 진입은 비번 불필요.
- 고객 모드 메뉴는 **4개**: 고객 · 계약관리 · 스타일 컨설팅 · 채촌. 이들은 **검색해 선택한 고객 1명**의 정보만 출력한다(다른 고객 리스트 비노출).
- 별도 고객 계정/저권한 세션은 만들지 않는다. 접근 제한은 프런트 모드 상태 + 화면 컨텍스트로 구현한다.
- 상세: **설계서 01**.

### D2. 진행상태 — 품목별 수동 완료 + 단계 완료버튼 게이팅
- 각 단계에서 **품목별 완료 처리는 수동 버튼**으로 한다.
- 단계의 **[전체 완료] 버튼**은 그 단계 대상 **전 품목이 완료되기 전에는 비활성**, **전 품목 완료 시 활성화**된다(PDF "상태완료 체크 조건").
- 즉 journey 단계 전진(완료)의 **활성화 조건을 품목별 완료 집계로 계산**한다. 자동 전진은 하지 않는다(활성화된 버튼을 담당자가 눌러 완료).
- PDF 2페이지 세부 단계·완료조건표를 그대로 코드화한다.
- 상세: **설계서 02**.

### D3. 렌탈 스타일 컨설팅 — 부위 × 컬러 × 사이즈 가용 선택
- 렌탈은 옵션 스테이지 선택이 아니라, **구성품(상의/하의/베스트)별로 컬러·사이즈를 지정해 가용한 렌탈 실물을 선택**한다.
- 기존 맞춤(CUSTOM) 옵션세션과 **분리된 렌탈 선택 흐름**을 신설하고, rentals 재고·가용검색(`rental-inventory.service.ts:523` availability)과 연계한다.
- 컬러 12색·사이즈는 기준정보 다운리스트 코드로 신규 구축.
- 상세: **설계서 04**.

### D4. 계약서 서명 — 태블릿 전자서명 캡처
- 전체 작성 후 **[서명하기]** 단계 → 손글씨 캔버스 서명을 **이미지로 캡처**해 계약 버전에 저장한다.
- 저장된 서명은 계약서 엑셀/화면 출력에 포함한다. 서명 없이 확정 불가(계약완료 조건).
- 상세: **설계서 03**.

### D5. 옵션/대분류 — 대분류 유지 + 옵션세트 부위별 세분
- 계약/주문 **대분류는 현행 SUIT/SHIRT/SHOES 유지**(재편 없음). plan_v2 line 160 질문에 대한 답: **현행 대분류·구성품 구조로 문제 없음.**
- 정장 옵션세트 내부를 **상의(JACKET)/하의(TROUSERS)/베스트(VEST) 부위 그룹**으로 세분해, 그룹별 이미지·옵션 금액을 관리한다.
- 수정=버전업(DRAFT→ACTIVE→RETIRED)은 **현행 구조 재사용**(신규 아님).
- 상세: **설계서 04**.

### D6. 결제·수선비용 — 완전 제거
- **payments 모듈·라우팅·테이블(`Payment`)과 `RepairRequest.cost` 컬럼을 삭제**한다.
- 고객/계약 화면의 **수금·미수·잔금 등 결제성 금액 표시를 제거**한다(고객 목록 `balanceAmount` 요약 등).
- 단, **계약 자체의 금액 필드(총액/계약금/잔액)와 계약서 총액 표시는 유지**한다(결제 수납과 계약 금액은 별개; 계약서 엑셀은 총액만 출력 — D7).
- 물리삭제 금지 원칙의 예외로, 본 항목은 요건상 명시적 제거로 처리한다(마이그레이션 §4).
- 상세: **설계서 06**.

### D7. 계약서 엑셀 — 표준 양식 자체 설계
- 작업지시서와 동일한 exceljs 패턴으로 **표준 계약서 엑셀 양식을 신설**한다.
- 표시 규칙(plan_v2):
  - **웹 화면**: 최초 = 품목·개수·가격 → 상세 / 스타일 옵션 추가 시 = 옵션명·가격 → 상세.
  - **엑셀**: 품목 = 세부 품목·개수 출력 / 가격 = **품목 세부 가격 제외, 전체 가격(총액)만** 출력.
- 서명 이미지(D4) 포함.
- 상세: **설계서 03**.

### D8. 채촌 앞마다/뒷마다 — 신규 필드 추가
- 조사 결과: `FRONT_RISE(앞밑위길이)`/`BACK_RISE(뒤밑윗길이)`는 **이미** 작업지시서 엑셀 '신체' 열(F, 67·69행)에 매핑됨(`work-order-template-map.ts:102-103`).
- 규칙("매핑되어 있으면 신규 추가")에 따라 **앞마다/뒷마다를 신규 하의 항목으로 추가**하고, 엑셀 **'하의 추가요청사항'의 앞/뒤로 매핑** 출력한다.
- 상세: **설계서 05**.

| 진행상태 | 품목별 단계완료 추적 테이블/컬럼(02장 확정) | D2 | 02 |
| `payments` 전체 | 테이블·모듈·라우팅 **삭제** | D6 | 06 |
| `repair_requests.cost` | 컬럼 **삭제** | D6 | 06 |
| 기준정보 | 렌탈 컬러/사이즈 코드 type 추가(admin-master `resolve()` 확장) | D3 | 04/06 |

FK는 전부 RESTRICT(구현표준 1.7). 제거(D6)를 제외한 나머지는 nullable/신규라 기존 데이터 무손상.

| 순번 | 범위 | 완료 기준 |
|---|---|---|
| S0 | 마이그레이션 골격 + 시드 보강(렌탈 컬러/사이즈, 진행단계 재정의) | `prisma migrate`·`seed` 재실행 안전, 기존 테스트 통과 유지 |
| S1 | **진행상태 재정의(02)** — PDF 단계·품목별 완료·게이팅 | 신규 테스트 통과, 8단계 전수 시연 |

| S5 | **채촌 확장(05)** — 이미지·cm/inch·앞마다/뒷마다 | 이미지 업로드·A4 인쇄·엑셀 매핑 확인 |
