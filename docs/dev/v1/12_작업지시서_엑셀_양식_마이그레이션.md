# 작업지시서 Excel — 실물 공장 양식(송파) 마이그레이션 v1.0

- 작성일: 2026-07-23
- 원본 양식: `docs/data/정장작업지시서 .xlsx` 의 **`작업지시서 (송파)`** 시트
- 템플릿 사본: `backend/src/modules/work-orders/templates/suit-work-order.xlsx` — **원본 파일 그대로**(바이트 복사)
- 구현: `work-order-excel.ts`(채우기) · `work-order-template-map.ts`(좌표·매핑표)
- 배경: 기존 MVP 양식은 "실제 공장 양식이 제공되면 셀 매핑 템플릿으로 교체한다"는 전제였다(통합설계서 §10.3). 이번에 양식이 확보되어 교체한다.

## 1. 방식

양식은 병합·인쇄영역·도식 이미지가 고정된 서식이라 **코드로 다시 그리지 않는다.** 템플릿 xlsx를 열어 **값 칸만 덮어쓰고** 저장한다. 좌표는 전부 병합 블록의 좌상단 셀이다.

- 나머지 시트(`바지`, `바지 (2)`, `자켓` — 호칭별 치수 대조표)는 **지우지 않고 출력 시 숨긴다.** 그 시트를 가리키는 정의된 이름(`ISAIA바지_노턱` 등 18개)이 함께 깨지기 때문이다. 파일을 열면 작업지시서 시트가 바로 보인다.
- **도식은 ExcelJS에 맡기지 않는다.** 양식의 도식은 그림뿐 아니라 **도형**(`xdr:sp` — 빨간 동그라미·점선 지시선)으로 돼 있는데 ExcelJS는 도형을 모른다. 읽을 때 전부 그림으로 뭉뚱그리고 쓸 때 크기·위치를 `0`으로 적어, 값만 채워도 도식이 검은 덩어리로 깨진다. 그래서 값(시트 XML)은 ExcelJS 결과를 쓰되 `xl/drawings/*`·`xl/media/*`는 템플릿 바이트를 그대로 덮어씌운다(`preserveTemplateDrawings`). spec이 바이트 동일성을 검증한다.
- 양식이 선택지를 인쇄해 두고 동그라미 치는 칸(주머니 플랩/아웃/입술/미니)은 `O` 표시 + 옅은 배경으로 마킹한다.
- 빌드 시 템플릿이 `dist`로 복사되도록 `nest-cli.json`에 `assets: ["**/*.xlsx"]`를 추가했다.

채촌 값을 **'신체' 열**에 넣는 근거: AICRM의 채촌은 신체 치수 기록이다(MEAS-001 "채촌 기록(신체 치수)"). 수정·완성 치수는 저장하지 않는다.

양식에 대응 칸이 없는 옵션(예: `LAPEL_HOLE` 라펠홀)과 채촌 항목(셔츠·구두)은 값을 버리지 않고 **추가요청사항(AA41)** 에 모아 적는다.

## 5. 화면 연동 (미리보기 · 내려받기)

파일은 서버에 버전으로 저장되지만 **브라우저로 내려주는 경로도, 양식 모습을 보는 경로도 없었다.** 둘 다 붙였다.

- **칸에 맞추기**: 양식은 손글씨용이라 값 칸 글꼴이 크게 잡혀 있어(예: 주문일 20pt) 날짜 하나도 넘친다. 값을 쓸 때 병합 블록 폭을 재서 넘치면 그 셀 글꼴만 줄인다(`fitFontSize`, 최소 8pt). **xlsx 파일과 미리보기가 함께** 고쳐진다.
- **미리보기**: 백엔드가 출력과 **같은 워크북**을 HTML 표로 그려 준다(`work-order-html.ts`). Excel과 같은 배치가 되도록 줄바꿈 칸이 아니면 한 줄로 두고 넘치면 옆으로 흘리며, 줄바꿈 칸은 행 높이에서 잘라낸다 — 표 칸에 가둬 줄바꿈시키면 행이 밀려 양식 전체가 어긋난다. 값 채우기 입력은 `buildExcelData()` 한 곳에서 만들어 미리 본 것과 내려받은 것이 어긋나지 않는다. 병합은 colspan/rowspan, 테두리·굵기·정렬·배경까지 옮긴다. 서식이 섞인 완결형 HTML이라 화면에서는 iframe(srcdoc)에 격리한다.
- **도식 겹쳐 그리기**: 표만 그리면 어느 부위를 가리키는 지시인지 알 수 없어 미리보기 구실을 못 한다. 템플릿 드로잉(그림 8·도형 22·연결선 17)을 직접 읽어(`work-order-drawing.ts`) 셀 앵커(열·행 + EMU 오프셋)를 격자 좌표로 환산하고, 그림은 data URI `<img>`, 빨간 동그라미는 원형 테두리 div, 지시선은 SVG `line`으로 표 위에 얹는다. ExcelJS가 도형을 못 읽으므로 필요한 요소만 뽑는 전용 파서를 쓰며, 도식은 데이터와 무관한 고정 요소라 프로세스당 한 번만 읽어 캐시한다.
- **내려받기**: 인증 헤더가 필요해 `<a href>`로는 못 받으므로 `client.downloadFile()`이 blob으로 받아 임시 링크를 클릭한다.

| 위치 | 버튼 | 동작 |
|---|---|---|
| 작업지시서 화면 `/work-orders/:orderItemId` | **[양식 미리보기]** | 출력 전 현재 옵션·채촌으로 그린 양식 표시 — **버전·파일이 생기지 않는다** |
| 〃 | **[Excel 출력]** | 새 버전 생성(`POST /order-items/:id/work-order-versions`) → 그 파일을 즉시 내려받기 |
| 〃 | **[최신본 받기 (Vn)]** | 저장된 최신 파일만 내려받기 — **버전이 늘지 않는다** |
| 〃 출력 이력 표 | **[보기] · [받기]** | 그 버전의 저장본을 화면에서 보거나 파일로 받기 |
| 제작 관리 코크핏 `/contracts/:id/production` | **[보기]** · **[Excel]** | 양식 미리보기 · 최신 출력본 바로 내려받기 (작업지시서 화면 안 거침) |

미리보기 API: `GET /order-items/:id/work-order/form-preview`(출력 전) · `GET /work-order-versions/:id/form-preview`(저장본). 둘 다 `{ versionNo, html }`을 준다.

"출력 = 새 버전"이라 단순 재열람까지 버전을 늘리지 않도록 **재열람 경로를 따로** 뒀다. 코크핏에서 바로 받으려면 버전 id·파일명이 필요해 `WorkOrderView`에 `currentVersionId`·`currentFileName`을 추가했다(`GET /production/items`, 미리보기 응답에도 `currentVersionId`).

내려받기 실패해도 버전은 이미 만들어졌으므로 출력 이력에서 다시 받으라는 안내를 띄운다.

## 6. 후속 과제 (채우려면 필요한 것)

1. **원단 마스터** (`fabrics`: 품번·색상·무늬·원단명) — 지금은 세션에 원단명 문자열 하나뿐. 양식 8칸(상·하의 각 4칸)이 이것 하나로 막혀 있다.
2. **고객 신체 프로필** (신장·체중·생년월일) — 키/몸무게·연령대 3칸.
3. **채촌 확장**: 수정치·완성치 열, 조끼 3항목, 바지기장 앞/뒤 분리.
4. **옵션 세트 확장**: 패드·어깨 특이사항·세빠·덧카라·라펠 폭·버튼 개수·오비폭·비조·앞주머니·뒷주머니·앞코 등 공장 양식 기준 세부 단계.
5. **체형 보정 항목**(학고·팔모양·다리모양·다리체형) — 채촌 화면의 `bodyNotes` 자유 텍스트를 구조화하면 매핑 가능.
